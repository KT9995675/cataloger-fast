## Актуализация v1.4 (июль 2026)

Дополнения к спецификации по результатам обсуждений и реализации. **Обновлять этот раздел после каждого согласованного архитектурного решения.**

### Листы

| Лист | v1.4 |
|---|---|
| `Catalog` | 11 колонок: `level_0`…`level_5`, **Размер** (MB), Утверждение, Редактор, Комментатор, Чтение. Скрытой колонки `id` **нет**. |
| `CatalogIndex` | **Новый, скрыт.** Строка view N = строка index N. Поля: `catalog_id`, `type`, `file_id`, `folder_code`, `name`, `approved`, `data_row_index`. |
| `CatalogData` | Без изменений по смыслу — источник правды. |

### Выбор строки в Catalog

1. Номер строки на листе `Catalog`.
2. Та же строка на `CatalogIndex` → `data_row_index`.
3. Одна строка `CatalogData` (полный узел). **Без** полного скана CatalogData при одиночном выборе.

### Отрисовка Catalog

- Файлы: имя в колонке `level_*` как **гиперссылка** (RichText + `webViewLink`).
- Папки: **жирный** шрифт в своей колонке `level_*`.
- Перед применением стилей — сброс форматирования дерева (`clearFormat`), иначе после перерисовок у папок остаётся оформление ссылок.
- Порядок: значения → сброс формата → текст/ссылки → жирный для папок.
- **Полная перерисовка** (`renderCatalogViewCore_`): синхронизация отображения прав, размеры с Drive, ссылки.
- **Лёгкая перерисовка** (`renderCatalogViewLight_`): после корзины/восстановления — без синхронизации прав и без скана размеров; **ссылки на файлы сохраняются**. Размеры в колонке могут быть пустыми до «Обновить дерево».

### Корзина (виртуальная, только CatalogData)

| Операция | Изменения в данных | Drive |
|---|---|---|
| В корзину | `trash_parent_id ← parent_id`, `parent_id ← id(Корзина)` | не трогается |
| Восстановление (быстрый путь) | обратно, если нет конфликта имён/`folder_code` | не трогается |
| Восстановление (полный путь) | как перенос между папками | переименование файлов при необходимости |
| Очистить корзину | удаление строк + файлов на Drive | физическое удаление |

После диалога подтверждения выделение в Sheets **сбрасывается** — операции корзины/восстановления передают **список id корней** из меню в core, а не читают выделение повторно.

### Импорт с Drive

- Staging: `_Import` внутри `root_folder_id` → promote в root (**редакторы**; см. batch ниже).
- **Drive API v3:** `addParents` / `removeParents` только в **optionalArgs** (4-й параметр) `Drive.Files.update`, не в теле `{ name: … }`.
- **Владелец таблицы:** copy/promote выполняются **в том же скрипте** (без HTTP на webapp); перенос своих файлов — напрямую в `root_folder_id`.
- **Редакторы:** обязателен webapp (`doPost`, секрет в Settings); URL с окончанием `/exec`.
- UI импорта: «Перенести все» / «Копировать все» — одно действие на весь набор (без радиокнопок на каждый файл).

#### Импорт v1.4.2 — трёхфазная модель (владелец, copy)

**Цель:** пользователь видит файлы в каталоге за ~15–25 с; физическое копирование на Drive — в фоне (~45–120 с на 100 файлов).

**Редакторы:** без изменений — `_Import`, webapp, `importCatalogDriveEntry` по файлу.

##### Фаза 1 — сбор (~10–20 с)

Один проход, один RPC (`startCatalogDriveImport`):

| Источник | Данные |
|---|---|
| Drive Batch `files.get` | count, `name`, `mimeType` (чанки по 50) |
| CatalogData (минимум) | родитель, соседи (уникальность имён) |

Права **источника** на Drive **не применяются** к копии — только права **родителя каталога** (наследование). Scan ACL источника — backlog / dry-run.

##### Фаза 2 — запись в каталог (~3–6 с)

1. План: уникальные имена, виртуальные папки по `path_segments`
2. Batch append строк **CatalogData** с `file_id` пустым (статус «копируется»)
3. View: ≤10 файлов — инкрементальная вставка; **51+ — отложить** до конца фона

##### Фаза 3 — фон + блокировка (~45–120 с)

1. Очередь в DocumentProperties (`pending_drive_import_job`)
2. Флаг `import_in_progress` + кооперативная блокировка скриптов (`assertCatalogImportNotBusy_`)
3. Триггер `processPendingDriveImportJob_`: Drive Batch copy (50) → обновить `file_id` → ACL триггер
4. Resume при лимите 6 мин; idempotency по `catalog_id` + `source_file_id`
5. По завершении: `renderCatalogViewLight_`, снять флаг; меню **Сбросить зависший импорт** (владелец)

##### Drive copy (отдельно от Sheets)

| Файлов | Метод | Оценка |
|---|---|---|
| 1 | `files.copy` | ~1–3 с |
| 2–50 | Batch HTTP | ~15–30 с |
| 51–100 | 2× Batch | ~30–60 с |

##### Блокировка

- `import_in_progress` проверяется в мутациях каталога (корзина, перенос, переименование, «Обновить дерево», …)
- Ручное редактирование листа **не** блокируется
- Строки с пустым `file_id` — без ссылки в Catalog до завершения copy

##### Backlog / улучшения

- Dry-run конфликтов имён до записи
- M3: ImportIndex-лист при N > 3000 строк
- Прогресс фона в Cache (не polling из диалога — GAS сериализует RPC)
- Email/toast по завершении bulk

#### Производительность импорта (v1.4.1 — superseded для copy владельца)

Superseded v1.4.2 для copy владельца. `importCatalogDriveBatch` остаётся для совместимости; диалог владельца вызывает `startCatalogDriveImport`.

### Утверждение (дополнение v1.4)

- Запись в CatalogData сразу; синхронизация прав на Drive — отложенный триггер (~2 с).
- Быстрый путь восстановления из корзины **не сбрасывает** `approved`.

### Процесс разработки

1. Обсуждение → согласование.
2. **Договорённость зафиксирована** → обновить этот раздел SPEC (+ HANDOFF при необходимости). Не откладывать до commit.
3. **«Пишем»** → код.
4. После проверки — CHANGELOG и commit по команде.

### Отрисовка: порядок шагов (важно для ссылок)

RichText-ссылки на файлы **сбрасываются** массовым форматированием диапазона (`setFontWeight`, `setBackground` и т.п.) на тех же ячейках.

**Согласованный порядок** в `renderCatalogViewCore_`:

1. `setValues` (дерево + права + размер)
2. `resetCatalogViewTreeFormatting_` (`clearFormat` колонок `level_*`)
3. `applyCatalogViewFolderBold_` — жирный для папок
4. `applyCatalogViewApprovalCells_`, полосы строк, формат колонки «Размер»
5. **`applyCatalogViewTreeNameCells_` — последним** среди операций, затрагивающих `level_*`

В v1.4.0 порядок был нарушен (ссылки до `applyCatalogViewFolderBold_` / полос) — файлы отображались как обычный текст. Исправление: вернуть ссылки в конец (как в v1.3.1: bold → links).

## 1. Концепция

Инструмент для управления файлами на Google Drive через Google Таблицу:

- **Виртуальное дерево папок** — только в таблице; физически все файлы лежат в **одной корневой папке** на Drive
- **Физические папки на Drive не создаются** — только файлы; виртуальные папки живут **только в CatalogData**
- **Интерфейс** — Google Таблица с группировкой строк (плюсики сворачивания)
- **Все операции** — через меню скрипта и HTML-диалоги; ручное редактирование `Catalog` запрещено (защищённые диапазоны)

## 2. Листы таблицы

| Лист | Видимость | Кто редактирует | Назначение |
|---|---|---|---|
| `Catalog` | Все | Только скрипт (защищённые диапазоны) | Дерево файлов/папок, права, утверждение |
| `Users` | Все | Редакторы таблицы | `email`, `name`, `active` |
| `Groups` | Все | Редакторы таблицы | Группы: одна строка = один участник |
| `Settings` | **Скрыт** | Только владелец | Настройки (ID корневой папки Drive, версия схемы) |

## 3. Виртуальная структура

### 3.1. Хранение

- Одна строка каталога = один файл или папка (папка — только в данных, без `file_id` на Drive)
- Папки и файлы на одном листе (без отдельного `Folders`)
- Дерево: `parent_id`, `folder_code`, `type`

### 3.2. Системные папки

| Папка | `folder_code` | Правила |
|---|---|---|
| **Каталог** | `0` | Корень; нельзя удалить, переместить, переименовать |
| **Корзина** | `99` | Виртуальная; нельзя удалить, переместить, переименовать |

### 3.3. Кодирование папок

- **Корень** (`Каталог`): папки `01`–`98` (макс. 98)
- **Внутри папки**: цифра `1`–`9` (макс. 9 подпапок)
- **Полный код**: `0237` = папка `02` → `3` → `7`
- **Лимит исчерпан** → создание запрещено, ошибка

### 3.4. Именование

- Имена на Drive и в каталоге **совпадают**, с префиксами
- **Файлы**: `{folder_code}_{имя}` → `0237_Отчёт.pdf`
- **Папки**: `{folder_code}_{имя}` → `0237_Проект`
- Пользователь задаёт имя **без префикса**; скрипт добавляет `folder_code_`
- При переносе папки — пересчёт кодов поддерева и переименование на Drive

### 3.5. Папки без объектов на Drive

- При создании виртуальной папки — только строка в CatalogData (`type=folder`, `file_id` пустой)
- `firstScan` не импортирует ярлыки с Drive

### 3.6. Визуализация

- Группировка строк пересчитывается автоматически после каждой операции, меняющей структуру

## 4. Лист `Catalog` — колонки

### Видимые

| Колонка | Описание |
|---|---|
| `name` | Имя с префиксом (как на Drive) |
| `type` | `folder` / `file` |
| `approved` | Кто утвердил; пусто = не утверждено |
| `editors` | Имена пользователей и групп |
| `commenters` | То же |
| `readers` | То же |

### Скрытые (защищённые)

| Колонка | Описание |
|---|---|
| `id` | UUID строки |
| `file_id` | ID файла на Drive (у папок пусто) |
| `folder_code` | Цифровой код папки |
| `parent_id` | `id` родителя |
| `mime_type` | MIME-тип |
| `permissions_json` | `[{subject, type: user/group, level: edit/comment/read}]` |

## 5. Пользователи и группы

### `Users`

- `email`, `name`, `active`
- Пополняется вручную; при первом сканировании — автосбор
- Права только людям из `Users`
- Доступ к таблице — вручную
- **Менеджер** = доступ **Редактор** к таблице
- Деактивация → снятие всех доступов

### `Groups`

- Одна строка = один участник
- Участники только из `Users`

## 6. Права доступа

### Уровни

Просмотр, Комментирование, Редактирование

### Наследование

- Директивное: права родителя → всё поддерево, лишние убираются
- Владелец аккаунта — полный доступ
- Новый элемент наследует права родительской папки

### Когда пересчитываются

1. Первое сканирование
2. Копирование / перенос (включая корзину)
3. Утверждение файла
4. Удаление пользователя
5. «Назначить права»

+ кнопка «Пересчитать всё» (только владелец). Каждое изменение → синхронизация на Drive.

### Назначение

- HTML-диалог; управление правами — только владелец

### Конфликты

- Права на Drive: `writersCanShare = false`
- Переименование на Drive: выравнивание при операциях каталога (каталог → Drive)

## 7. Утверждение

- Только **файлы**
- Утвердить может любой с правом «Редактирование»
- После утверждения: все → «Просмотр»; отменить нельзя
- Правки — копия `_v2`, `_v3`… в той же папке, права от родителя

## 8. Операции

Меню «Каталогизатор»; команды к **выделенным строкам**.

HTML-диалоги: права, создать, переименовать, перенести/копировать, импорт, утвердить.

| Операция | Кто |
|---|---|
| Создание, копирование, загрузка, импорт, перенос, переименование, корзина, восстановление, утверждение, копия для правок, группы | Редакторы файла / таблицы |
| Назначить права | Владелец |
| Очистить корзину, Пересчитать всё | Владелец |

### Копирование vs перенос

- **Копировать**: оригинал остаётся, новый `file_id`, права от целевой папки
- **Перенести**: тот же `file_id`, новый `parent_id`/префикс, права от целевой папки

## 9. Первое сканирование

1. Виртуальная папка «Каталог»
2. Файлы из физической корневой папки Drive
3. Уникальные пользователи → `Users`
4. Смена владельца, если не ты
5. Текущие права → `permissions_json`

## 10. Корзина

- Виртуальная папка `99`
- Удаление = перемещение в корзину (**только смена `parent_id` в CatalogData** — см. Актуализация v1.4)
- Восстановление — в `trash_parent_id` или «Каталог» при недоступном родителе
- Очистка — физическое удаление (владелец)

## 11. Защита

- Защищённые диапазоны на `Catalog`
- `writersCanShare = false`
- Имена на Drive выравниваются при операциях каталога
