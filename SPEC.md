## Cataloger Fast — спецификация v0.1

Цель: каталогизатор должен работать **мгновенно** в 99% пользовательских операций. Любые медленные операции Google Drive выполняются **асинхронно**, вне критического пути UI.

---

## 1. Модель данных (Google Sheets)

Храним только метаданные каталога, без сортировок и без “перерисовок” всего дерева.

### 1.1 Листы

- `Tree` (служебный): структура виртуальных папок
  - `folder_id` (UUID)
  - `parent_folder_id`
  - `label` (имя папки без префиксов)
  - `prefix_code` (опционально, для поиска/навигации, не в имени файла)
  - `created_at`, `updated_at`

- `Files` (служебный): файлы и привязка к папкам
  - `catalog_id` (UUID записи)
  - `folder_id` (куда положен файл в дереве)
  - `file_id` (Drive ID, может быть пустым пока pending)
  - `source_file_id` (Drive ID источника для импорта, если применимо)
  - `display_name` (имя в каталоге, без префиксов)
  - `status`: `ready | pending_publish | pending_copy | failed`
  - `last_error`
  - `created_at`, `updated_at`

- `CatalogACL` (служебный): виртуальные права на объекты каталога
  - `subject` (email)
  - `role`: `read | comment | edit` (для каталога)
  - `folder_id` или `catalog_id`
  - Группы — это только “набора разрешённых пользователей” в UI, на Drive не отражаются.

- `DriveGrants` (служебный журнал): выдачи доступа на Drive “перед открытием”
  - `file_id`
  - `grantee_email`
  - `permission_id` (важно для быстрого revoke)
  - `granted_at`
  - `expires_at` (опционально; если нет — отзываем ночным триггером)

## 2. Политика Google Drive (безопасность)

### 2.1 Базовое состояние

- Все файлы в рабочей папке каталога на Drive имеют доступ “закрыто всем”, кроме владельца/сервиса.
- Каталог управляет выдачей доступа, Drive права **не являются источником истины** для доступа пользователей.

### 2.2 Выдача доступа перед открытием (только файлам)

При попытке открыть файл:

1) Проверить по `CatalogACL`, что текущий пользователь имеет право открыть файл.
2) Выдать доступ **только одному пользователю** на конкретный `file_id`:
   - типично 1 операция `Drive.Permissions.create` (или update)
3) Сохранить `(file_id, email, permission_id, granted_at[, expires_at])` в `DriveGrants`.
4) Отдать ссылку на `file_id` пользователю.

Целевая задержка: \(0.3–1.5\) сек, 95-й перцентиль \(2–5\) сек.

## 3. Импорт

Каталог должен обновляться мгновенно; работа с Drive — в фоне.

### 3.1 Импорт “копировать” (default)

1) Сразу создать строки в `Files` со статусом `pending_copy` и заполненным `source_file_id`.
2) Фоновый воркер копирует `source_file_id` → целевую Drive-папку (чанки по 50 через batch HTTP).
3) По готовности: записать `file_id`, статус `ready`.

### 3.2 Импорт “привязать без копии” (опция)

1) Создать строку в `Files` сразу с `file_id = source_file_id`, статус `ready`.
2) Drive не трогаем (кроме выдачи доступа перед открытием).

---

## 4. Мгновенные операции (только в Sheets)

- Создание папки: запись в `Tree`.
- Перемещение файла между папками: update `folder_id` в `Files`.
- Права: update `CatalogACL` (без Drive).
- Поиск: по `display_name` и/или `prefix_code` (без Drive).

Целевая задержка: \< 1–2 сек на одиночную операцию.

---

## 5. Фоновые процессы

### 5.1 Воркер импорта (copy/publish)

- Очередь задач хранится в `DocumentProperties` или в служебном листе.
- Воркер выполняется триггером порциями, выдерживая лимит времени запуска.
- Должен быть идемпотентен: повторный запуск не создаёт дубликаты.

### 5.2 Ночной отзыв доступов (4:00)

Идея: отзывать только те файлы, которым выдавался доступ за сутки.

1) Выбрать уникальные `file_id` из `DriveGrants` за последние сутки.
2) Для каждой записи удалить `permission_id`.
3) Очистить/архивировать записи за сутки.

Оценка: ~1 операция на выдачу; 100 выдач ≈ 1–3 мин.

---

## 6. Ограничения и сознательные компромиссы

- Drive права могут “временно” расходиться с виртуальными правами, но базовое состояние Drive закрыто всем, поэтому утечек не должно быть.
- Отзыв “при закрытии файла” не гарантируется (браузер/клиент), используем TTL и/или ночной revoke.
