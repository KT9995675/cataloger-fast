## 0. Сводка спецификации (актуальная)

### 0.1 Продукт

- **Total Commander** над Google Drive: веб-приложение (GAS + clasp), **две панели**; drag-and-drop — в спецификации, **в коде ещё нет**.
<!-- OLD: «две панели, drag-and-drop» как будто уже есть — DnD не реализован -->
- **Файлы** — одна **плоская папка** на Drive (человеческие имена, дубликаты имён допустимы).
- **Дерево, метаданные, права** — Google Таблица (7 листов + `DocumentProperties`).
- **Быстрота UI**; медленные операции (импорт, Drive) — **в фоне**; прогресс — **строка статуса внизу** (§2.6, §2.7).

### 0.2 Интерфейс

- **Обе панели** — только **каталог** (корень или виртуальная папка, в т.ч. корзина). Импорт — кнопка **«Импорт»** в нижнем командном ряду (§2.6) → модальное окно (v1: один файл по ссылке Drive; §9.10).
- **Нижняя зона** — два ряда (§2.6): командный (**Импорт**, **F5/F6/F8** — кнопки для Менеджера/Управляющего) + подсказки навигации; статусный ряд (сообщения, email).
- **Список:** сначала **папки (жирным)**, потом **файлы**; двойной щелчок — вход/открытие.
- **Столбцы:** Имя | Утверждено | Редакторы | Корректоры | Читатели | Размер | Дата изменения.
- **Права в столбцах** — **эффективные** (наследование + группы). Пусто → `—`.
- **Двойной щелчок по ячейке прав** → окно ACL: группы `#…`, пользователи, 4 radio (§2.2.4). Drive при этом **не читаем**.
<!-- OLD: «полный список раскрывается двойным щелчком» — см. окно ACL выше -->
- **Утверждено** (только файлы): в UI v1 пока отображение ✓ / пусто; чек-бокс + подтверждение — **ещё не в UI** (§7, §17).
<!-- OLD: чек-бокс → подтверждение → имя утвердившего (§7) — целевое поведение, UI TBD -->
- **Дата изменения:** файл — с Drive (обновлять при добавлении в папку и при открытии); папка — дата создания в каталоге, не меняется.
- **Размер папки** — рекурсивная сумма файлов.
- **Контекстного меню нет.** Операции: горячие клавиши §2.4, кнопки §2.6; drag-and-drop — **ещё нет**.
- **Тип файла** — бейдж в столбце **Имя** (`Files.mime_type`); отдельного столбца нет.
- **Навигация** — при старте `getCatalogSnapshot()` в память браузера; листание **локально** (§2.7).
- **F5/F6** → цель = **неактивная панель**; **F7** — **Создать** (папка или Google-файл, §13.5); **F8** → корзина; **Shift+F6** — переименование.
<!-- OLD: F7 — создать папку -->

### 0.3 Права

- **Два слоя:** роль входа (§14.4) + права на объект (§4).
- **Роли входа:** Пользователь | Менеджер | Управляющий (один = владелец таблицы).
- **Права на объект:** нет прав | читатель | комментатор | редактор.
- Листание — **все видят всё**; открытие — по правам; на Drive — **временный доступ**, сброс **04:00 Москва**.
- Наследование: смена прав папки → **перезапись** вложенных; смена файла → не влияет на родителя.
- Персональные права **> группа**; среди групп — **максимум**.
- **Утверждён:** редакторы → комментаторы; далее редактор не выдаётся (§7).

### 0.5 Импорт

- **v1 (✅):** один файл по ссылке Drive → папка активной панели; copy/move; участники → `Users` (§9.10).
- **Далее:** папки, локальные файлы, фоновые `Jobs`, полный навигатор (§2.5, §9).

### 0.5a Скорость и снимок каталога (§2.7)

1. Старт: **один** `getCatalogSnapshot()` → память браузера (Tree/Files + эффективные ACL; **без Drive**).
2. Листание панелей — **только из снимка**.
3. Операции **сразу пишут в таблицу**; UI после успеха: F6/F8/rename — **локальный патч** снимка; copy/import/ACL — **повторный** снимок.
4. Запись move: колонка **одним** `setValues` (не цикл `setValue`).

**Отклонено:** держать правки только в RAM и заливать **всю** таблицу раз в 10 мин — риск потери данных и last-write-wins в многопользовательском режиме. Таблица = истина всегда.

### 0.6 Модель данных

- **Листы:** `Tree`, `Files`, `Users`, `ACL`, `Groups`, `GroupMembers`, `Jobs` — поля §3.6–3.8.
- **Properties:** `SCHEMA_VERSION`, `CATALOG_ROOT_FOLDER_ID`, `CATALOG_VIRTUAL_ROOT_FOLDER_ID`, `CONTROLLER_EMAIL`, `SETUP_AT`.
- **Корневая виртуальная папка:** `parent_folder_id` пусто; рабочие папки и корзина — **внутри** неё.

### 0.7 Инициализация (только Web App)

- Владелец таблицы: ссылка на **пустую** свою папку Drive + **имя корня** → `setupCatalog()`.
- Setup **один раз**; триггер отзыва доступов при setup; обе панели по умолчанию на **корне**.

### 0.8 Назначение прав

- **Управляющий** — права на объекты в **корне** виртуального дерева.
- **Менеджер** — на **любую папку**, где он **редактор** (и внутри).
- UI: dblclick по столбцам прав → список `#группы` + пользователи + 4 radio (§2.2.4).
- Смена прав **папки** → `setObjectAcl` перезаписывает ACL **всего поддерева** (§4.4).

### 0.9 Аутентификация и доступ к операциям

- **Google OAuth**, email в `Users`; отдельного пароля нет.
- **Штатные операции:** `canRunCatalogOperations` = `manager` / `controller` / владелец таблицы / `CONTROLLER_EMAIL` (§14.9).
- **Открытие файла** — из `Users` + права на объект (`openCatalogFile`).

### 1.1 Приоритеты

- **Отображение в каталоге** (навигация, появление файла после добавления) — **мгновенно**, это критический путь UI.
- **Медленные операции** (импорт на Drive, копирование, перемещение, массовые действия) — **в фоне**, без блокировки интерфейса.

## 2. Интерфейс

| Параметр | Решение |
|---|---|
| Платформа | Веб-приложение |
| Компоновка | Две панели, логика визуализации как в Total Commander |
| Манипуляции | Перетаскивание мышью (drag-and-drop) между панелями и внутри них |
| Строка статуса | Внизу окна — **два ряда** §2.6: командный (кнопки + подсказки F-клавиш) и статусный (сообщения, прогресс) |

### 2.1 Две панели (как Total Commander)

- **Обе панели одинаковы** по возможностям — симметричные независимые навигаторы.
- Каждая панель показывает **свою текущую локацию** и навигируется **независимо** от другой.
- **Локация панели** может быть:
  - **виртуальная папка каталога**, или
  - **место на Google Drive** вне каталога (для импорта и сравнения). <!-- OLD: см. ниже -->
- **Обе панели всегда** показывают **место в каталоге** — **корень** или **одна из виртуальных папок** (в т.ч. корзина).
- Импорт с Drive / с компьютера — **отдельный сценарий** *(TBD: диалог, drag-and-drop в панель и т.п.)*, не через навигацию по внешнему Drive в панели. <!-- OLD: см. §2.5 -->
- **Копирование / перемещение / drag-and-drop** — **между панелями** и **внутри панели**, по тем же правилам, что в Total Commander.
- Типичный сценарий: одна панель — **каталог**, вторая — **источник на Drive** или **другая папка каталога**. <!-- OLD: обе панели — только каталог; см. §2.1 -->
- Типичный сценарий: **две папки каталога** в разных ветках (копирование/перемещение F5/F6).
- После **первого входа** (и по умолчанию при открытии приложения) **обе панели** показывают **корневую виртуальную папку** каталога (§15.2).

### 2.2 Список папок и файлов в панели

#### 2.2.1 Порядок и открытие

- В списке **сначала папки**, **потом файлы**.
- **Папки** отображаются **жирным**.
- **Файл** открывается **двойным щелчком** (с учётом прав на объект — §4, §12).
- **Папка** открывается **двойным щелчком** (навигация внутрь).

#### 2.2.2 Столбцы

| Столбец | Содержимое |
|---|---|
| **Имя** | Папка (жирным) или файл; слева — **бейдж типа** (DIR / DOC / PDF / ZIP …), без отдельного столбца |
<!-- OLD: только имя без пиктограммы типа -->
| **Утверждено** | Только у **файлов** — см. §2.2.4 |
| **Редакторы** | Список пользователей с правом **редактор** на объект |
| **Корректоры** | Список пользователей с правом **комментатор** на объект *(в UI: «корректоры»)* |
| **Читатели** | Список пользователей с правом **читатель** на объект |
| **Размер** | Размер **файла** или **папки** (суммарно для папки *(TBD: алгоритм)* ) |
| **Размер** | Размер **файла**; для **папки** — **рекурсивная** сумма размеров всех файлов во **всех вложенных подпапках**. <!-- OLD: см. строку выше -->
| **Дата обновления** | Дата последнего обновления объекта |
| **Дата обновления** | Дата последнего обновления **на Google Drive** (файла или метаданных файлов внутри папки *(TBD: для папки — max по вложенным или только прямые файлы)*). <!-- OLD: см. строку ниже -->
| **Дата создания** | **Дата создания** объекта; задаётся **один раз** при появлении в каталоге (для файла — с Drive при импорте/добавлении; для папки — при создании папки в каталоге). **После этого не меняется** (перемещение, переименование, смена прав, правки на Drive — дату **не обновляем**). <!-- OLD: см. строку ниже -->
| **Дата изменения** | **Файл** — дата **последнего изменения** на Google Drive. **Папка** — дата **создания** папки в каталоге; считаем, что папка **больше не менялась** после создания (не пересчитываем при изменениях внутри). |

**Когда обновляем дату изменения файла** (перечитываем с Drive и записываем в каталог):

1. Когда файл **добавился в папку** (импорт, копирование, перемещение в виртуальную папку).
2. Когда файл **открывали**.

В обоих случаях в столбец попадает **дата последнего изменения на Drive** (не дата операции в каталоге).

#### 2.2.3 Сортировка

- Сортировка по **имени** или **любому столбцу**.

#### 2.2.4 Столбцы «Редакторы / Корректоры / Читатели»

- Показываем **эффективные права** на объект — с учётом **наследования от папок** (§4.4) и **групп** (§11), а не только явно назначенные на этот файл/папку.
- Если в столбце **есть пользователи** — **двойным щелчком** по ячейке открывается окно прав (§4.5).
- Если **никого нет** — показываем **прочерк** (`—`).

**Окно назначения прав (реализовано):**

- Источник данных — **только каталог** (листы `Users`, `Groups`, `ACL`); **Drive не читаем**.
- Сначала **все группы** с префиксом **`#`**, затем **все пользователи** каталога.
- Напротив каждой строки — **4 радиокнопки**: **Редактор** | **Корректор** | **Читатель** | **Без прав**.
- При открытии радиокнопки выставлены по **текущим эффективным правам** на объект (`getObjectAclForEdit`); сохранение — `setObjectAcl`.
- Режим **только просмотр** — если нет права редактировать ACL.

#### 2.2.5 Столбец «Утверждено»

- Только у **файлов** (у папок столбец пустой или неактивен).
- До утверждения — **чек-бокс**.
- При установке чек-бокса — **запрос подтверждения**.
- После утверждения (§7):
  - чек-бокс **заменяется** на **email/имя пользователя**, который утвердил файл;
  - права на объект меняются по правилам §7.
- Снятие «утверждён» — *(TBD: см. §7.2)*.

#### 2.2.6 Связь с моделью данных

- Отображение списка и столбцов определяет минимальные поля листов `Tree` и `Files` (§3.4) — детали столбцов *(TBD)*. <!-- OLD: см. §3.6 -->
- Поле **`created_at`** в `Tree` / `Files`: записывается при создании, **иммутабельно**. <!-- OLD: см. ниже -->
- **`Tree`**: `folder_created_at` — дата создания папки; **не обновляется**.
- **`Files`**: `drive_modified_at` — дата последнего изменения файла на Drive. **Обновляется**, когда файл **добавлен в папку** или **открыт** (перечитываем с Drive). <!-- OLD: TBD про синхронизацию -->

### 2.3 Выделение и операции (без контекстного меню)

- **Контекстное меню** (правый щелчок) в **первой версии не делаем**.
- Операции выполняются над **выделенными** объектами в панели — **как в Total Commander** (файлы и/или папки).
- Способы запуска операций *(TBD)*: **горячие клавиши**, **панель кнопок**, **drag-and-drop** между панелями. <!-- OLD: горячие клавиши — §2.4 -->
- Выделение: **один объект**, **несколько** (Ctrl/Shift), **оба типа** — файлы и папки в одном выделении *(TBD: детали)*.
- **Сейчас в коде:** выделение **только одиночное** (клик по строке). Ctrl/Shift/Ctrl+A и операции над набором — **ещё не реализованы** (§17).

- Диалог выбора папки **не показываем** (достаточно выставить нужную папку во второй панели).
- Действуют проверки прав (§14.6, §14.7): **редактор** на исходной и целевой папке каталога.
- Обе панели — **только каталог**; внешний Drive в панели **не показываем** (§2.1).

**Восстановление из корзины:** отдельной функции **нет** — то же **F6**: корзина на активной панели, целевая папка на неактивной (§13.3).

**F8 — удаление в корзину:** только **Менеджер / Управляющий** + право **редактор** на **папку** объекта (§13.2, §14.6).

### 2.7 Скорость навигации по каталогу

**Цель:** листание панелей — **мгновенно** (§1.2); задержка допустима на **старте** и на **записи** операции (ограничение GAS).

**Модель (п.1–3):**

1. При старте — **один** запрос `getCatalogSnapshot()`: весь каталог (Tree/Files + эффективные ACL) в **память браузера**. Drive не читаем.
2. Навигация по панелям — **только из снимка** (без `google.script.run`).
3. Операции (F5/F6/F8, rename, import, ACL) — **сразу пишут в таблицу** на сервере; после успеха UI обновляет снимок (локальный патч для F6/F8/rename; для copy/import/ACL — повторный `getCatalogSnapshot`).

**Сервер:**

- `getCatalogSnapshot()` — полный снимок для клиента.
- `listFolderContents` / `listFolderContentsBatch` — остаются (отладка / запасной путь).
- `applyFileFolderUpdates_` — колонка одним `setValues` (§ раньше).

**Клиент:**

- `catalogSnapshot` — `foldersById` / `filesById`; листинг папки строится локально.
- F6/F8 — патч `folderId` / `parentFolderId` в снимке + перерисовка открытых панелей.
- Shift+F6 — патч имени в снимке.
- Copy / import / ACL / открытие файла — `reloadCatalogSnapshot_`.

<!-- OLD: folderCache по папкам + listFolderContents на каждый первый вход -->
<!-- OLD: после перемещения — полный invalidate + refreshPanelsForFolders через list -->

**Не делаем:** заливка всей таблицы раз в N минут; серверный кеш между вызовами GAS.

**Оценка порядка времени** (≈1000 файлов / 100 папок, типичный GAS):

| Сценарий | Ожидание |
|---|---|
| Старт (один snapshot) | 2–5 с (холодный старт GAS выше) |
| Листание папки после snapshot | &lt;50 мс |
| F6 одного файла (batch write + локальный патч UI) | в основном время серверного move; UI без второго list |
| Повторный вход в ту же папку | мгновенно (снимок) |

Узкие места по-прежнему: **SpreadsheetApp** и **round-trip** `google.script.run`, не Drive (для list/move).

## 3. Хранение данных

### 3.1 Google Drive

- Все файлы каталога лежат в **одной физической папке** на Google Drive.
- Папка принадлежит **владельцу каталога**.
- Внутри папки **нет подпапок** — только «плоский» список файлов.
- Имена файлов на Drive — **исходные «человеческие» названия**.
- Google Drive **не требует уникальности имён** в одной папке: у каждого файла свой `file_id`.

### 3.2 Google Таблица

- **Виртуальное дерево папок** хранится в Google Таблице.
- **Служебная информация** (метаданные, права, статусы) — в Google Таблице.
- Связь записи каталога с файлом на Drive — через `file_id`.

### 3.3 Один экземпляр каталога

- **Один каталогизатор = одна Google Таблица** + **одна плоская папка** на Drive.
- Несколько независимых каталогов в одной таблице **не предусмотрено**.

## 4. Права доступа

### 4.1 Общие принципы

- Каталогизатор — **единственный источник истины** по правам доступа.
- На Drive по умолчанию доступ к каждому файлу имеет **только владелец каталога**.
- Права задаются **отдельно для каждого файла** и **отдельно для каждой папки** (виртуальной).
- Уровни прав (как в Google Drive):
  - **нет прав**
  - **читатель**
  - **комментатор**
  - **редактор**

### 4.2 Навигация vs открытие

- При **листании панелей** (без открытия файла) пользователь **видит все файлы и папки** каталога.
- Ограничение по правам срабатывает при **открытии** файла.

### 4.3 Выдача доступа на Drive

- При **открытии** конкретного файла пользователю выдаётся временный доступ на Drive с уровнем, соответствующим его правам в каталогизаторе.
- **Ежедневно в 04:00** все ранее выданные доступы **обнуляются** (отзываются).
- Часовой пояс сброса: **Москва (UTC+3)**.

### 4.4 Наследование прав

1. **Смена прав папки** → все вложенные файлы и подпапки **получают те же права** (включая объекты, у которых права были заданы индивидуально — они **перезаписываются**).
2. **Смена прав конкретного файла или подпапки** → **не влияет** на права родительской папки.

### 4.5 Кто назначает права на объекты

- **Управляющий** задаёт права на **все файлы и папки в корне** каталога (верхний уровень виртуального дерева).
- **Менеджеры** могут **назначать права** на объекты **внутри своих папок** — в тех виртуальных папках, где они управляют доступом *(TBD: «своя папка» = папка, где у менеджера право «редактор» на объект)*. <!-- OLD: см. ниже -->
- **Менеджеры** могут **назначать права** на объекты **внутри своих папок**. **Своя папка** — виртуальная папка, где у менеджера есть право **редактор** на объект (§4). <!-- OLD: см. ниже -->
- **Менеджеры** могут **назначать права** на **саму свою папку** (где они **редактор**) и на объекты **внутри неё** (вложенные папки и файлы). **Своя папка** — виртуальная папка, где у менеджера право **редактор** на объект (§4). <!-- OLD: см. ниже -->
- **Менеджеры** могут **назначать права** на **любую папку и подпапки**, где у них есть право **редактор** на объект (§4) — не только на одну «свою» ветку, а на **каждую** такую папку в дереве.
- При назначении прав действуют те же правила **наследования** (§4.4).

## 7. Статус «утверждён»

Файл может иметь статус **«утверждён»**.

При установке статуса «утверждён»:

1. Все пользователи, у которых было право **редактор**, получают право **комментатор**.
2. После утверждения **никому** не выдаётся право **редактор** на этот файл (в том числе при наследовании прав от папки и при явной выдаче).

*(TBD: кто может устанавливать/снимать статус «утверждён».)* <!-- OLD: см. ниже -->

**Кто может устанавливать и снимать «утверждён»:**

- **Владелец каталога** (роль входа **Управляющий** — §14.4; по умолчанию всегда имеет право **редактор** на объекты).
- Любой пользователь с правом **редактор** на данный файл.

### 7.1 Сохранность статуса «утверждён»

- Свойство **«утверждён»** хранится в каталоге (таблица) и **сохраняется** при **перемещении в корзину** и при **перемещении из корзины** (F6, §13.3).
- Попадание в корзину **не снимает** статус «утверждён».

### 7.2 Отображение в UI

- Столбец **«Утверждено»** в списке файлов — §2.2.5.
- После утверждения в столбце показывается **пользователь, который утвердил** (вместо чек-бокса).

## 9. Импорт файлов

### 9.1 Копирование vs перемещение

- Режим импорта (**копирование** или **перемещение**) выбирает **пользователь** для каждого файла или для **папки целиком** (со всеми вложенными файлами).
- **Копирование** — оригинал остаётся в источнике; в плоскую папку каталога попадает копия.
- **Перемещение** — оригинал исчезает из источника; файл оказывается в плоской папке каталога.

### 9.2 Владелец файла

- Если у импортируемого файла **другой владелец** (не владелец каталога) — доступен **только режим копирования**.
- Цель: **все файлы в каталоге принадлежат владельцу каталога**.

### 9.3 Пакетная обработка

- Нужна **пакетная обработка** для **массового импорта** старых файлов.

### 9.4 Пользователи при импорте

- При импорте файла **пополняем список пользователей** каталогизатора: добавляются те, у кого **были доступы** к импортируемому файлу (на Drive до импорта).
- Новым пользователям при импорте автоматически назначается роль входа **Пользователь** (§14.4).
- При импорте переносим **только права** на объекты (читатель / комментатор / редактор). Статусы вроде **«утверждён»** при импорте **не переносим**.

### 9.8 Права при импорте папки (ускорение)

- Для **ускорения импорта** права **не копируются по каждому вложенному файлу** отдельно.
- Права берутся **с импортируемой папки** (источник на Drive) и задаются на **корень** импортированной ветки в каталоге.
- Всё **внутри** наследует права от этой папки по правилам §4.4.
- Если у вложенных файлов на Drive были **разные права** — это **осознанное упрощение**: внутри ветки права **выравниваются** по корню импортированной папки.
- При необходимости менеджер **поправит права** уже в каталоге.

*(TBD: откуда импортируем — только Drive или также загрузка с компьютера; асинхронность массового импорта.)* <!-- OLD: см. ниже -->

### 9.5 Источники импорта

- **Google Drive** — другие папки и файлы на Drive.
- **Локальный компьютер** — загрузка через браузер (выбор файлов, drag-and-drop).

### 9.6 Скорость и фоновая обработка

- **Ключевой приоритет** — **скорость отображения** файла в каталоге (файл сразу виден в интерфейсе после добавления записи).
- Сам **импорт на Drive** (копирование, перемещение, загрузка) выполняется **в фоне** — не блокирует UI.

### 9.7 Отображение во время фонового импорта

- Файл в панели каталога **выглядит как обычно** — сразу после добавления записи, без отличий по виду строки.
- **Прогресс фоновых операций** (импорт и прочие фоновые задачи) отображается **отдельно** — в специальном месте интерфейса *(TBD: где именно — статус-бар, панель задач и т.п.)*. <!-- OLD: см. ниже -->
- **Прогресс фоновых операций** — **строка статуса внизу** окна (как в Total Commander).

### 9.9 UI импорта и структура папок

- Запуск импорта — **кнопка «Импорт»** → **модальное окно** (§2.5).
- В модальном окне **просматриваем и выбираем** источник: **локальные** файлы/папки или **свой Google Drive** (не панели каталога).
- Цель: **текущая папка активной панели** каталога.
- **Структура папок источника сохраняется** в виртуальном дереве (`Tree`) под выбранной целевой папкой.
- Файлы на Drive — в **плоской** физической папке каталога (§3.1).
- Права при импорте папки — по упрощённым правилам §9.8 (с корня импортированной ветки).
- Режим **копирование / перемещение** — выбор пользователя **на файл** или **на всю папку/группу** сразу (§2.5).
- Подтверждение — кнопка **«Импортировать»**; отдельного предпросмотра результата в каталоге **нет**.

### 9.10 Импорт v1 (реализовано)

**Функция:** `importDriveFile(input)` — `src/CatalogImport.gs`.

**Вход:**

| Поле | Описание |
|---|---|
| `targetFolderId` | Виртуальная папка активной панели |
| `driveFileUrl` | Ссылка или id файла на Google Drive |
| `mode` | `copy` (по умолчанию) или `move` |

**Правила:**

- Только **Менеджер / Управляющий** (`assertCanRunCatalogOperations_`) + **редактор** на целевую папку.
- Файл копируется/перемещается в **плоскую** папку каталога на Drive (`CATALOG_ROOT_FOLDER_ID`).
- Запись в `Files` создаётся **сразу**; операция на Drive в v1 — **синхронная** (фоновые `Jobs` — позже, §9.6).
- Если файл **не принадлежит** `CONTROLLER_EMAIL` — только **copy** (ошибка `COPY_ONLY` при `move`).
- Участники исходного файла (редакторы, читатели, комментаторы) → автоматически в `Users` с ролью **Пользователь** (§9.4).
- UI: модальное окно «Импорт с Google Drive» — поле URL + radio copy/move (§2.5 v1).

**Не в v1:** импорт папок, локальная загрузка, пакетный импорт, фоновая очередь.

## 13. Операции файлового менеджера

### 13.1 Базовые операции (v1)

В первой версии поддерживаются все операции:

- **Копирование** — между виртуальными папками (и между панелями). На Drive создаётся **вторая физическая копия** файла (не ярлык, не общая ссылка).
- **Перемещение** — между виртуальными папками.
- **Переименование** — изменение отображаемого имени в каталоге *(TBD: меняется ли имя файла на Drive)*. <!-- OLD: см. ниже -->
- **Переименование** — имя меняется **и в каталоге (таблица)**, **и на Google Drive**.
- **Удаление** — перенос в **корзину** (см. §13.2).
- **Удаление в корзину (F8)** — только **Менеджер** или **Управляющий** + право **редактор** на **папку**, где лежит объект (§14.6).

### 13.2 Корзина

- **Корзина** — **особая виртуальная папка** в каталоге. Реализация: **системная папка в `Tree`** (§3.5).
- Корзина **видна всем** в списке папок при навигации (§3.5).
- При «удалении» файл **перемещается в корзину** в дереве каталога.
- Статус **«утверждён»** при этом **сохраняется** (§7.1).
- Файл **не удаляется физически** с Google Drive.
- Удалять в корзину могут только **Менеджер / Управляющий** при праве **редактор** на соответствующую **папку** (§14.6).

<!-- OLD: TBD восстановление из корзины — решено: F6, §13.3 -->

### 13.3 Восстановление из корзины

**Решение:** отдельной функции **«Восстановить»** **нет**. Возврат файла/папки из корзины — обычное **перемещение F6**:

1. В **активной** панели открыть **корзину** (`__TRASH__`).
2. В **неактивной** панели открыть **целевую** виртуальную папку.
3. Выделить объект в корзине → **F6** (или кнопка «F6 Перем.»).

Технически — тот же `moveCatalogItems`; проверки §14.6–14.7 (редактор на исходной папке-корзине и на целевой).

Статус **«утверждён»** при перемещении из корзины **сохраняется** (§7.1).

### 13.5 Создать файл (реализовано)

**UI:** одна кнопка / **F7 Создать** → диалог «Что создать»: **Папку** или тип Google-файла. Папка → `createCatalogFolder`; файл → `createCatalogFile`.
<!-- OLD: отдельная кнопка «Создать файл»; F7 только папка -->

**Поведение (файл):**

- Цель: **текущая папка активной панели**.
- Тип: любой из нативных Google-форматов (Документ, Таблица, Презентация, Форма, Рисунок, Vids, Сайт, Мои карты, Jamboard) — выбор в диалоге.
- Файл создаётся в **плоской** папке каталога на Drive; запись в `Files`.
- **Владелец на Drive** = `CONTROLLER_EMAIL` (передача через `setOwner` после создания).
- Создатель получает право **редактор** в ACL каталога и editor на Drive.
- Нужно право **редактор** на целевую папку (Управляющему — всегда); не только роль Менеджер.
- После создания файл **открывается** в новой вкладке.

**Реализация:** `createCatalogFile` — `src/CatalogCreateFile.gs` (Drive API v3 через `UrlFetchApp` + `DriveApp.setOwner`). Scope: `script.external_request` в `appsscript.json`.

**Ограничение:** передача владельца зависит от политики Google Workspace / аккаунта; вне одного домена `setOwner` может завершиться ошибкой `OWNERSHIP_TRANSFER_FAILED`.

### 13.4 Очистка корзины

- **Окончательное удаление** с Google Drive — **служебная функция**, доступна только роли входа **Управляющий** (§14.4).
- Действие: **«Очистить корзину»** — все файлы из корзины **физически удаляются** с Drive.
- До очистки корзины файлы **хранятся бессрочно** (на Drive не удаляются).

## 14. Вход в приложение и роли

> **Доступ к функциям приложения** определяется **только тремя глобальными ролями** (ниже). <!-- OLD: см. §14.4 — «роли входа» -->
> Права на конкретный файл/папку (§4) — **отдельный слой**: уровень доступа к объекту и выдача прав на Drive при открытии. <!-- OLD: уточнено в §14.3 -->

### 14.1 Терминология (чтобы не путаться)

| Термин | Что означает |
|---|---|
| **Роли входа** | **Пользователь**, **Менеджер**, **Управляющий** — кто какие **функции приложения** может выполнять (§14.4) |
| **Права на объект** | **нет прав / читатель / комментатор / редактор** — доступ к **конкретному файлу или папке** (§4) |

Слово **«редактор»** в §4 — это **право на объект**, не роль входа. Роль входа **«Менеджер»** — другое.

### 14.2 Аутентификация

- Вход в веб-приложение — по **авторизации**: **email** и **пароль**.
- Email **заранее внесён** в список каталога.
- *(TBD: хранение паролей; связь email с Google-аккаунтом при открытии файла на Drive.)* <!-- OLD: см. ниже -->

**Вход через Google-аккаунт (OAuth):**

- Отдельного пароля каталога **нет**.
- Пользователь авторизуется **Google-аккаунтом** в браузере.
- Каталог проверяет: email из Google-сессии **заранее внесён** в список пользователей → назначается **роль входа** (§14.4).
- Для **открытия файлов** на Drive пользователь должен быть залогинен в **тот же Google-аккаунт** — на него выдаётся временный доступ (§4.3).

### 14.3 Два слоя доступа после входа

1. **Роль входа** — какие **функции каталогизатора** можно **запускать** в приложении (штатные операции, служебные функции). <!-- OLD: см. §14.5 -->
2. **Права на файлы и папки** (§4) — **работа с файлами** после входа: открытие, уровень доступа на Drive, наследование, группы, «утверждён» и т.д.

### 14.4 Три роли входа

| Роль входа | Функции приложения |
|---|---|
| **Пользователь** | Вход; просмотр списков папок и файлов; **открытие** файлов (с учётом прав на объект — §4) |
| **Пользователь** | Вход; просмотр списков папок и файлов. **Не запускает функции каталогизатора** (копирование, перемещение, импорт, управление правами и т.п.). **Работа с файлами** — только в соответствии с **правами на объект** (§4): открытие и уровень доступа на Drive. <!-- OLD: см. строку выше и §14.5 -->
| **Менеджер** | Всё у пользователя + **все штатные операции** (копирование, перемещение, переименование, удаление в корзину, импорт и т.п.) |
| **Менеджер** | **Все штатные операции** каталогизатора (копирование, перемещение, переименование, удаление в корзину, импорт и т.п.). Для операции нужны **редакторские права на объект** (§4): на **файл** и/или **папку**, где выполняются изменения. <!-- OLD: см. строку выше и §14.6 -->
| **Управляющий** | Всё у менеджера + **служебные функции** (очистка корзины — §13.4 и др.). **Владелец файлов на Drive** и каталога — §3.1 |
| **Управляющий** | Всё у менеджера + **служебные функции** (очистка корзины — §13.4 и др.). **Владелец файлов на Drive** и каталога — §3.1. **Всегда один** — владелец каталога (§14.8). <!-- OLD: см. строку выше -->

<!-- OLD: §14.2 Три глобальные роли (Пользователь / Редактор / Владелец) — см. §14.4 (Пользователь / Менеджер / Управляющий) -->
<!-- OLD: TBD про глобальную роль «Редактор» vs право «редактор» — см. §14.1 и §14.3 -->

*(TBD: нужна ли роль входа «Менеджер» для штатных операций над файлом, если на объект уже есть право «редактор», или достаточно только прав на объект.)* <!-- OLD: см. §14.5 -->

### 14.5 Роль «Пользователь» и права на объект

- **Пользователь** **не может запускать** функции каталогизатора (штатные и служебные операции в UI).
- **Работа с файлами** — **только по правам на объект** (§4): открыть файл, получить на Drive уровень **читатель / комментатор / редактор** в соответствии с выданными правами.

*(TBD: нужны ли права «редактор» на объект, чтобы **Менеджер** мог выполнять штатные операции над этим файлом, или роли «Менеджер» достаточно.)* <!-- OLD: см. §14.6 -->

### 14.6 Роль «Менеджер» и права на объект

- Штатные операции может выполнять только **Менеджер** (или **Управляющий**).
- Дополнительно для каждой операции нужны **редакторские права на объект** (§4) — на **папку**, где происходят изменения, и при необходимости на **файл**.
- Без права **редактор** на соответствующую папку/файл операция **недоступна**, даже при роли «Менеджер».
- В т.ч. **удаление в корзину (F8)** — только Менеджер/Управляющий + **редактор** на **папку** объекта.

### 14.8 Управление пользователями и ролями входа

- **Добавлять пользователей** в каталог и **назначать роли входа** могут: **Управляющий** и **Менеджер**. <!-- OLD: см. ниже -->
- **Управляющий всегда один** — это **владелец каталога** (§3.1). Роль **не назначается** другим пользователям.
- **Управляющий** может добавлять пользователей и назначать роли **Пользователь** и **Менеджер**.
- **Менеджер** может добавлять пользователей и назначать роли **Пользователь** и **Менеджер** (роль **Управляющий** — только у владельца каталога).

*(TBD: может ли Менеджер назначать роль «Управляющий» или только «Пользователь» / «Менеджер».)* <!-- OLD: см. §14.8 — Управляющий один, владелец каталога -->

### 14.7 Копирование и перемещение между папками

- Для **копирования** и **перемещения** между виртуальными папками нужны права **редактор** на **обе** папки: **исходную** и **целевую**.
- Цель: **не допустить** ситуации, когда доступ к «секретному» файлу получит пользователь, которому права **не выдавались** (через перенос файла в папку с более широкими правами).

### 14.9 `canRunCatalogOperations` (реализовано)

Флаг в `getWebAppBootstrap()` — определяет видимость кнопок **Импорт / F5 / F6 / F8** и доступ к соответствующим серверным функциям.

**`true`, если выполняется хотя бы одно:**

| Условие | Источник |
|---|---|
| `loginRole === 'manager'` | лист `Users` |
| `loginRole === 'controller'` | лист `Users` |
| email совпадает с `CONTROLLER_EMAIL` | `DocumentProperties` |
| email = владелец Google Таблицы | `DriveApp.getFileById(spreadsheetId).getOwner()` |

**`false`** для роли **Пользователь** без совпадения с владельцем/`CONTROLLER_EMAIL`.

На сервере дополнительно: `assertCanRunCatalogOperations_(loginRole)` в `CatalogMove.gs` / `CatalogImport.gs` и проверки **редактор** на объекты (§14.6–14.7).

## 15. Инициализация каталога (setup)

### 15.1 Когда запускается

- При **первом открытии** веб-приложения, если каталог **ещё не инициализирован** (нет листов / нет `SCHEMA_VERSION` в `DocumentProperties` — §3.11).
- Показываем экран/диалог **подтверждения** инициализации.
- После **подтверждения** пользователем — setup выполняется **автоматически** (отдельный запуск из редактора Apps Script **не нужен**).
- В диалоге подтверждения Владелец вводит **ссылку на плоскую папку** на Google Drive (папка **создана им заранее** — §15.2).
- В том же диалоге Владелец задаёт **имя корневой виртуальной папки** каталога в `Tree` (§15.2 п.3).

*(TBD: кто видит диалог и может подтвердить — только владелец таблицы / первый вошедший через Google; текст подтверждения.)* <!-- OLD: см. ниже -->

- Подтвердить инициализацию может **только Владелец** Google Таблицы (он же станет **Управляющим** каталога — §14.8).
- Остальные пользователи при неинициализированном каталоге видят **сообщение**, что каталог ещё не настроен *(TBD: текст)*.

**Только из веб-приложения:**

- Вся инициализация (диалог, ввод ссылки и имени корня, вызов setup) — **только через веб-приложение** (§10).
- Ручной запуск `setupCatalog` / `setupCatalogSheets` в редакторе Apps Script — **только для разработки и отладки**, не для пользователей продукта.

### 15.2 Что делает setup

1. Создаёт **листы** и **заголовки** столбцов (§3.4–3.8), если отсутствуют.
2. Создаёт **плоскую папку** на Google Drive (§3.1) → `CATALOG_ROOT_FOLDER_ID` в `DocumentProperties`. <!-- OLD: см. ниже -->
2. **Плоская папка** на Drive **уже создана Владельцем** до setup. В диалоге инициализации Владелец указывает **ссылку** на неё → из ссылки извлекается `CATALOG_ROOT_FOLDER_ID` → записывается в `DocumentProperties` (§3.11).

**Проверки папки (иначе setup запрещён, показываем ошибку):**

- Папка **принадлежит Владельцу** таблицы.
- Папка **пустая** (нет файлов и подпапок).
3. Создаёт **системную папку корзины** в `Tree` (`__TRASH__`, §3.5).
3. Создаёт **корневую виртуальную папку** каталога в `Tree` (верхний уровень дерева; все рабочие папки — внутри неё). *(TBD: имя по умолчанию, например «Каталог».)* <!-- OLD: см. ниже -->
3. Создаёт **корневую виртуальную папку** в `Tree` с **именем**, которое Владелец **задал в диалоге** setup; все рабочие папки — **внутри** неё → `CATALOG_VIRTUAL_ROOT_FOLDER_ID` в `DocumentProperties` (§3.11).
4. Создаёт **системную папку корзины** в `Tree` (`__TRASH__`, §3.5) **внутри корневой** виртуальной папки. <!-- OLD: было п.3 без корня; корзина на верхнем уровне -->
4. Записывает `SCHEMA_VERSION`, `SETUP_AT`, `CONTROLLER_EMAIL` (§3.11).
5. Добавляет **Владельца таблицы** в `Users` с ролью **Управляющий** (`controller`) — §14.8. <!-- OLD: «инициатора» — только владелец таблицы -->
6. Создаёт **триггер** ежедневного **отзыва временных доступов** на Drive — **04:00 по Москве** (§4.3).
<!-- OLD: п.6 «Идемпотентность» — см. §15.3 -->

### 15.3 Setup один раз; миграции при разработке

- В **готовом продукте** setup выполняется **один раз**. Повторная инициализация **не предусмотрена**.
- Если каталог **уже инициализирован** (`SCHEMA_VERSION` и `CATALOG_ROOT_FOLDER_ID` в `DocumentProperties`) — setup **не запускаем**, работаем как обычно.
- При **несогласованности** данных (листы есть, Properties нет или не совпадают) — **ошибка**, работа **блокируется** *(TBD: текст для Владельца)*.
- **Изменение структуры** листов во время **разработки** — отдельная **временная служебная функция** (миграция), **не** повторный setup.

### 16.4 Исправления при разработке (зафиксировано)

| Проблема | Причина | Решение |
|---|---|---|
| `file.getOwners is not a function` в setup / bootstrap | В DriveApp нет `getOwners()` | `getOwner()` — один владелец (§10.1) |
| `userIterator.hasNext is not a function` при импорте | `getEditors()` возвращает массив | Обход массива в `collectDriveFileParticipantEmails_` (§10.1) |
| Кнопки Импорт/F5/F6/F8 не работали | Были только текстовые подсказки | Реальные `<button>` + `canRunCatalogOperations` (§2.6, §14.9) |
| Медленный вход в Корзину / повторная навигация | Повторные round-trip к серверу | `getCatalogSnapshot` + локальная навигация (§2.7) |
<!-- OLD: listFolderContentsBatch + folderCache -->
| Медленный F6/F8 | `setValue` по ячейке + полный reload панелей | `setValues` колонки + локальный патч снимка (§2.7) |
| `UrlFetchApp.fetch`: недостаточно разрешений | Нет scope `script.external_request` | Добавлен в `appsscript.json`; нужен clasp push + повторная авторизация / новый deploy Web App |
| Тип файла не виден в списке | `mime_type` не хранился | Поле `Files.mime_type` (schema 0.2) + квадратные SVG в «Имя»; автоапгрейд; backfill MIME при snapshot |
| Google Docs не открываются по dblclick, Sheets — да | `DriveApp.getUrl()` для Docs часто даёт неудачную ссылку | Канонический URL по MIME (`docs.google.com/document/.../edit`) |

### 16.5 Порядок реализации (сессия разработки)

1. `setupCatalogSheets` → `isCatalogInitialized` → `setupCatalog`
2. `doGet` + `getWebAppBootstrap` + экраны setup
3. `listFolderContents` + двухпанельный UI
4. ACL read (`getEffectiveAclDisplay`) → `openCatalogFile` → `setObjectAcl`
5. `moveCatalogItems` (F6/F8) → `importDriveFile` → командная строка → `copyCatalogItems` (F5)
6. UI ACL (radio) + `getObjectAclForEdit`
7. `renameCatalogItem` (Shift+F6)
8. Ускорение: batch `setValues` + локальный патч move → **`getCatalogSnapshot` + локальная навигация**
9. `createCatalogFolder` (F7)

### 16.6 Отклонённые / отложенные идеи по скорости

| Идея | Вердикт |
|---|---|
