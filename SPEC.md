## Cataloger Fast — спецификация v0.1

Цель: каталогизатор должен работать **мгновенно** в 99% пользовательских операций. Любые медленные операции Google Drive выполняются **асинхронно**, вне критического пути UI.

---

## 0. Инициализация (setup)

### 0.1 `setupSchemaFast(catalogRootFolderId)`

Назначение: создать (если отсутствуют) служебные листы и зафиксировать конфигурацию каталога в свойствах документа.

**Контракт:**

- Идемпотентна: повторный запуск не меняет данные.
- Создаёт отсутствующие листы и записывает строку заголовков (row 1), замораживает 1-ю строку.
- Если лист существует, но заголовки не совпадают **строго 1-в-1** с ожидаемыми — ошибка `SCHEMA_MISMATCH` (миграции делаются отдельными функциями, не в `setupSchemaFast`).
- Если в свойствах уже задан другой root-id — ошибка `CATALOG_ROOT_MISMATCH` (автоподмена запрещена).

**Хранение конфигурации** (DocumentProperties):

- `FAST_SCHEMA_VERSION = "0.1"`
- `FAST_CATALOG_ROOT_FOLDER_ID = "<Drive folder id>"`

## 1. Модель данных (Google Sheets)

Храним только метаданные каталога, без сортировок и без “перерисовок” всего дерева.

### 1.1 Листы

- `Tree` (служебный): структура виртуальных папок
  - `folder_id` (UUID)
  - `parent_folder_id`
  - `label` (имя папки без префиксов)
  - `prefix_code` (опционально, для поиска/навигации, не в имени файла)
  - `created_at`, `updated_at`

- `Files` (служебный): файлы и привязка к папкам
  - `catalog_id` (UUID записи)
  - `folder_id` (куда положен файл в дереве)
  - `file_id` (Drive ID, может быть пустым пока pending)
  - `source_file_id` (Drive ID источника для импорта, если применимо)
  - `display_name` (имя в каталоге, без префиксов)
  - `status`: `ready | pending_copy | pending_move | failed`
  - `last_error`
  - `created_at`, `updated_at`

- `CatalogACL` (служебный): виртуальные права на объекты каталога
  - `subject` (email)
  - `role`: `read | comment | edit` (для каталога)
  - `folder_id` или `catalog_id`
  - Группы — это только “набора разрешённых пользователей” в UI, на Drive не отражаются.

- `DriveGrants` (служебный журнал): выдачи доступа на Drive “перед открытием”
  - `file_id`
  - `grantee_email`
  - `permission_id` (важно для быстрого revoke)
  - `granted_at`
  - `expires_at` (опционально; если нет — отзываем ночным триггером)

## 2. Google Drive: хранилище и безопасность

### 2.1 Физическое хранилище (инварианты)

- Единственная рабочая папка каталога на Drive — `FAST_CATALOG_ROOT_FOLDER_ID` (задаётся при `setupSchemaFast`).
- **Все файлы каталога** физически лежат **только** в этой папке. Режима «link» (ссылка на файл вне папки) **нет**.
- Виртуальное дерево (`Tree`) существует **только в Sheets**; физические подпапки на Drive **не создаются** (файлы — плоско в root).
- Любой `Files.file_id` (когда `status = ready`) указывает на файл **внутри** `FAST_CATALOG_ROOT_FOLDER_ID`.

### 2.2 Владелец файлов

- **Владелец каталога** = **владелец Spreadsheet** (и скрипта, привязанного к ней).
- **Owner всех файлов** в папке каталога = владелец каталога.
- При импорте чужого файла: только **copy** → transfer ownership владельцу каталога → файл в root.

### 2.3 Попадание файла в папку каталога

Файл попадает в `FAST_CATALOG_ROOT_FOLDER_ID` **только** одним из двух способов:

| Способ | Когда | Результат на Drive |
|---|---|---|
| **copy** | Чужой owner **или** пользователь выбрал «копировать» | Новый `file_id` в root |
| **move** | Owner исходника = владелец каталога **и** пользователь выбрал «перенести» | Тот же `file_id`, перенос в root |

**Правило выбора при импорте:**

- Режим (**copy** / **move**) — **опция в UI импорта**; **по умолчанию — copy**.
- Если owner исходника **≠** владелец каталога → доступен **только copy** (move недоступен / отклоняется с ошибкой).

Других способов (link, alias, файл вне root) **нет**.

### 2.4 Базовое состояние прав

- Все файлы в рабочей папке каталога на Drive имеют доступ “закрыто всем”, кроме владельца каталога.
- Каталог управляет выдачей доступа; Drive-права **не являются источником истины** для доступа пользователей.

### 2.5 Выдача доступа перед открытием (только файлам)

При попытке открыть файл:

1) Проверить по `CatalogACL`, что текущий пользователь имеет право открыть файл.
2) Выдать доступ **только одному пользователю** на конкретный `file_id`:
   - типично 1 операция `Drive.Permissions.create` (или update)
3) Сохранить `(file_id, email, permission_id, granted_at[, expires_at])` в `DriveGrants`.
4) Отдать ссылку на `file_id` пользователю.

Целевая задержка: \(0.3–1.5\) сек, 95-й перцентиль \(2–5\) сек.

## 3. Импорт и добавление файлов

Каталог обновляется мгновенно; операции Drive — в фоне.

### 3.1 Copy (default для чужих / когда нужна копия)

1) Сразу создать строку в `Files`: `status = pending_copy`, заполнен `source_file_id`, `file_id` пустой.
2) Фоновый воркер: `files.copy` → `FAST_CATALOG_ROOT_FOLDER_ID` (batch, чанки по 50).
3) По готовности: записать `file_id`, `status = ready`.

### 3.2 Move (только если owner исходника = владелец каталога)

1) Сразу создать строку в `Files`: `status = pending_move`, заполнен `source_file_id`, `file_id` пустой.
2) Фоновый воркер: `files.update` с `addParents`/`removeParents` → перенос в `FAST_CATALOG_ROOT_FOLDER_ID`.
3) По готовности: `file_id = source_file_id`, `status = ready`.

Если пользователь выбрал move, но owner исходника ≠ владелец каталога → ошибка `MOVE_NOT_ALLOWED` (или UI не даёт выбрать move).

## 4. Мгновенные операции (только в Sheets)

Целевая задержка: \< 1–2 сек на одиночную операцию.

### 4.1 `createFolderFast(parentFolderId, label, prefixCode?)`

Создание виртуальной папки: одна запись в `Tree`, без Drive.

**Вход:**

- `parentFolderId` — UUID родителя из `Tree`, или `''` для корневой папки
- `label` — имя папки (без префиксов в имени)
- `prefixCode` — опционально, для колонки `prefix_code`

**Поведение:**

- Нормализует `label` (`trim`, `/` и `\` → `-`)
- Если `label` пустой после нормализации → `INVALID_LABEL`
- Если `parentFolderId` не пустой и такого `folder_id` нет в `Tree` → `PARENT_NOT_FOUND`
- Если среди siblings (один `parent_folder_id`) уже есть такой `label` → `DUPLICATE_LABEL` (без авто-суффикса)
- Генерирует `folder_id = UUID`, пишет строку в `Tree`

**Выход:**

```javascript
{
  ok: true,
  folder_id,
  parent_folder_id,
  label,
  prefix_code,
  created_at,
  updated_at
}
```

### 4.2 `createFileRecordFast(folderId, sourceFileId, displayName, mode?)`

Создание записи файла в `Files` (Sheets only); Drive copy/move — позже воркером.

**Вход:**

- `folderId` — UUID виртуальной папки из `Tree`
- `sourceFileId` — Drive ID исходника
- `displayName` — имя в каталоге (без префиксов)
- `mode` — `'copy' | 'move'`, **default: `'copy'`**

**Поведение:**

- Нормализует `displayName` (`trim`, `/` и `\` → `-`)
- Если `displayName` пустой → `INVALID_DISPLAY_NAME`
- Если `sourceFileId` пустой → `INVALID_SOURCE_FILE_ID`
- Если `folderId` не найден в `Tree` → `FOLDER_NOT_FOUND`
- Если `mode = move` и owner исходника ≠ владелец каталога → `MOVE_NOT_ALLOWED`
- Пишет строку в `Files`:
  - copy → `status = pending_copy`, `file_id` пустой
  - move → `status = pending_move`, `file_id` пустой

**Выход:**

```javascript
{
  ok: true,
  catalog_id,
  folder_id,
  source_file_id,
  display_name,
  status,
  file_id: '',
  created_at,
  updated_at
}
```

### 4.3 Прочие мгновенные операции (planned)

- Перемещение файла между виртуальными папками: update `folder_id` в `Files`.
- Права: update `CatalogACL` (без Drive).
- Поиск: по `display_name` и/или `prefix_code` (без Drive).

### 4.4 Меню Spreadsheet (UI)

При открытии таблицы (`onOpen`) создаётся меню **«📁 Каталогизатор Fast»**.

Пункты добавляются по мере готовности функций:

- **⚙️ Инициализация схемы** → `setupSchemaFast`
- **📂 Создать корневую папку** → `createFolderFast('', label)`

- **📄 Добавить запись файла** → `createFileRecordFast(...)` (dev: через prompt)
- **🔄 Обновить меню** → пересоздать меню без перезагрузки страницы

## 5. Фоновые процессы

### 5.1 Воркер импорта (copy / move)

- Очередь задач хранится в `DocumentProperties` или в служебном листе.
- Воркер выполняется триггером порциями, выдерживая лимит времени запуска.
- Должен быть идемпотентен: повторный запуск не создаёт дубликаты.

### 5.2 Ночной отзыв доступов (4:00)

Идея: отзывать только те файлы, которым выдавался доступ за сутки.

1) Выбрать уникальные `file_id` из `DriveGrants` за последние сутки.
2) Для каждой записи удалить `permission_id`.
3) Очистить/архивировать записи за сутки.

Оценка: ~1 операция на выдачу; 100 выдач ≈ 1–3 мин.

## 6. Ограничения и сознательные компромиссы

- Drive права могут “временно” расходиться с виртуальными правами, но базовое состояние Drive закрыто всем, поэтому утечек не должно быть.
- Отзыв “при закрытии файла” не гарантируется (браузер/клиент), используем TTL и/или ночной revoke.
